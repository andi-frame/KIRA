# KIRA MVP Fase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Membangun prototype KIRA (backend FastAPI + app Flutter) yang menjalankan alur demo Raka penuh: onboarding → check-in → proyeksi diabetes 10 tahun + what-if → rekomendasi cek → input hasil → kalibrasi → mode pengelolaan.

**Architecture:** Logika angka berupa fungsi murni di `backend/app/core_calc/`, dibungkus tipis sebagai tool LangChain. Satu graf LangGraph 8 node (`run_kira_graph`) melayani semua input chat. Flutter hanya merekam input, memanggil API, dan menampilkan hasil.

**Tech Stack:** Python 3.11, FastAPI, Pydantic v2, SQLAlchemy 2.0 async + Alembic, PostgreSQL 16 (Docker), LangGraph + langchain-anthropic, pytest; Flutter (riverpod, dio, go_router, record, image_picker, fl_chart, flutter_secure_storage); Playwright untuk uji UI web.

**Spec:** `docs/superpowers/specs/2026-10-14-kira-mvp-design.md` (konteks produk: `docs/konsep_kira.md`, `docs/rencana_implementasi.md`)

## Global Constraints

- Angka (risiko, gizi, target) hanya dari `core_calc`; LLM dilarang menyebut angka tanpa memanggil tool. `user_id` tidak pernah menjadi argumen yang diisi LLM; disuntikkan dari state graf.
- Python ≥3.11, Pydantic v2, SQLAlchemy 2.0 async; versi `langgraph`/`langchain-*` dikunci di `requirements.txt` dan impor dicocokkan dengan dokumentasi versi terpasang.
- Bahasa produk: "proyeksi risiko", "skrining", "saran gaya hidup"; balasan memakai "masih sesuai targetmu hari ini", tidak pernah "aman" atau "kamu menderita". Tidak ada saran obat/dosis/diagnosis.
- Rumus kurva: `R(t) = 1 − (1 − p10)^(t/10)`, t = 0..10 tahun. Hipertensi Fase 1 = kategori tensi saja. Tidak ada WhatsApp, keluarga, Framingham, scheduler.
- Setiap konstanta klinis hidup di `core_calc/constants.py` dengan komentar `# TODO-VERIFY: <sumber>`; nilai sementara boleh dipakai untuk development, tidak boleh masuk materi submission.
- Semua data seed/demo adalah data dummy. Secret hanya di `.env` (tidak di-commit). Semua query difilter per `user_id`.
- Foto diproses lalu dibuang; hanya hasil ekstraksi disimpan.
- Komit kecil per task; pesan commit diakhiri baris `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Pesan kosong / hanya spasi / tanpa media ke `/chat/message` → 422, LLM tidak dipanggil. (Task 11)
2. LLM atau STT gagal/timeout, atau keluaran ekstraksi melanggar skema → balasan ramah "coba lagi", tidak crash, tidak ada angka karangan, log tidak tersimpan setengah. (Task 10, 11)
3. Makanan tak dikenal → `found: false`, balasan meminta klarifikasi, tidak mengarang gizi. (Task 6, 11)
4. Profil belum lengkap (tanpa tanggal lahir/tinggi/berat) → `hitung_risiko` mengembalikan rentang terlebar atau `needs_profile`, tidak error 500. (Task 3, 12)
5. Hasil cek mustahil (gula darah 5 atau 5000, sistolik 400) atau tidur lintas tengah malam (tidur 02:00, bangun 07:00; tidur 23:00, bangun 06:00) → ditolak/divalidasi benar, tidak tersimpan sebagai data valid. (Task 5, 12)
